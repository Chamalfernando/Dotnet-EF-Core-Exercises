==============================================================================
 EFCoreExcercises - Developer Guide
 How to add features, controllers, services, and dependencies
==============================================================================

Project          : EFCoreExcercises (ASP.NET Core 8 Web API, controller-based)
Target framework : net8.0
Style            : Controllers + Swagger (see Program.cs)
All commands below are run from the project folder:
    D:\DOTNET_WORKS\Dotnet-EF-Core-Exercises\EFCoreExcercises
Shell assumed    : PowerShell (Windows). Commands also work in bash.

------------------------------------------------------------------------------
 0. ONE-TIME PREREQUISITES
------------------------------------------------------------------------------

Check the SDK is installed:
    dotnet --version          (should be 8.0.x or compatible)

Install the EF Core command-line tool (global, once per machine):
    dotnet tool install --global dotnet-ef

If it is already installed, update it instead:
    dotnet tool update --global dotnet-ef

Verify:
    dotnet ef --version

NOTE: If "dotnet ef" is not recognized after install, close and reopen the
terminal so the updated PATH is picked up (the tool lives in
%USERPROFILE%\.dotnet\tools).

 1. RECOMMENDED FOLDER STRUCTURE
------------------------------------------------------------------------------

Keep things organized as the project grows. Create these folders as needed:

    Controllers/        -> API controllers (already exists)
    Models/             -> entity classes (database tables)
    Data/               -> DbContext + EF configuration
    DTOs/               -> request/response data transfer objects
    Services/           -> business logic (interfaces + implementations)
    Validators/         -> FluentValidation validators
    Migrations/         -> auto-generated by EF Core (do not hand-edit)

Create a folder from the terminal:
    New-Item -ItemType Directory Models, Data, DTOs, Services, Validators

 2. INSTALLING NUGET DEPENDENCIES
------------------------------------------------------------------------------

General command form:
    dotnet add package <PackageName>
    dotnet add package <PackageName> --version <x.y.z>     (pin a version)

After adding packages, restore + build to confirm everything resolves:
    dotnet restore
    dotnet build

--- 2.1 Entity Framework Core (with SQL Server provider) -------------------

    dotnet add package Microsoft.EntityFrameworkCore
    dotnet add package Microsoft.EntityFrameworkCore.SqlServer
    dotnet add package Microsoft.EntityFrameworkCore.Design
    dotnet add package Microsoft.EntityFrameworkCore.Tools

  * .Design is REQUIRED for migrations to work (dotnet ef uses it).
  * Prefer a different database? Swap the provider package:
        SQLite      -> Microsoft.EntityFrameworkCore.Sqlite
        PostgreSQL  -> Npgsql.EntityFrameworkCore.PostgreSQL
        MySQL       -> Pomelo.EntityFrameworkCore.MySql
    (Keep .Design regardless of provider.)

--- 2.2 FluentValidation ---------------------------------------------------

    dotnet add package FluentValidation.AspNetCore

  This brings in FluentValidation plus the ASP.NET Core integration helpers.

--- 2.3 Serilog ------------------------------------------------------------

    dotnet add package Serilog.AspNetCore
    dotnet add package Serilog.Sinks.Console
    dotnet add package Serilog.Sinks.File

  Add more sinks later as needed (e.g. Serilog.Sinks.Seq,
  Serilog.Sinks.MSSqlServer).

--- 2.4 Optional but common ------------------------------------------------

    dotnet add package AutoMapper                  (object-to-object mapping)
    dotnet add package Swashbuckle.AspNetCore      (already installed - Swagger)

------------------------------------------------------------------------------
 3. SETTING UP EF CORE (DbContext + connection string)
------------------------------------------------------------------------------

STEP 3.1 - Create an entity in Models/  (example: Models/Product.cs)

    namespace EFCoreExcercises.Models;

    public class Product
    {
        public int Id { get; set; }
        public string Name { get; set; } = string.Empty;
        public decimal Price { get; set; }
    }

STEP 3.2 - Create the DbContext in Data/  (Data/AppDbContext.cs)

    using EFCoreExcercises.Models;
    using Microsoft.EntityFrameworkCore;

    namespace EFCoreExcercises.Data;

    public class AppDbContext : DbContext
    {
        public AppDbContext(DbContextOptions<AppDbContext> options)
            : base(options) { }

        public DbSet<Product> Products => Set<Product>();
    }

STEP 3.3 - Add a connection string to appsettings.json

    "ConnectionStrings": {
      "DefaultConnection": "Server=localhost;Database=EFCoreExcercises;Trusted_Connection=True;TrustServerCertificate=True;"
    }

  (For SQL Server in Docker / SQL auth use:
   "Server=localhost,1433;Database=EFCoreExcercises;User Id=sa;Password=Your_password123;TrustServerCertificate=True;")

STEP 3.4 - Register the DbContext in Program.cs
  Add BEFORE 'var app = builder.Build();'

    using EFCoreExcercises.Data;
    using Microsoft.EntityFrameworkCore;

    builder.Services.AddDbContext<AppDbContext>(options =>
        options.UseSqlServer(
            builder.Configuration.GetConnectionString("DefaultConnection")));

------------------------------------------------------------------------------
 4. EF CORE MIGRATIONS (creating / updating the database schema)
------------------------------------------------------------------------------

Create the first migration (run after the DbContext is set up):
    dotnet ef migrations add InitialCreate

Apply migrations to the database (creates/updates tables):
    dotnet ef database update

Typical loop whenever you change an entity or DbContext:
    1. edit / add the entity class
    2. dotnet ef migrations add <DescriptiveName>     e.g. AddProductTable
    3. dotnet ef database update

Other useful migration commands:
    dotnet ef migrations list                 list all migrations
    dotnet ef migrations remove               remove the LAST migration
                                              (only if NOT yet applied)
    dotnet ef database update <MigrationName>  roll forward/back to a point
    dotnet ef database update 0                revert ALL migrations
    dotnet ef migrations script                generate a SQL script

TIP: If you have multiple DbContexts, add: --context AppDbContext

 5. ADDING A SERVICE (business logic + dependency injection)
------------------------------------------------------------------------------

Pattern: define an interface, write an implementation, register it in DI.

STEP 5.1 - Interface  (Services/IProductService.cs)

    using EFCoreExcercises.Models;

    namespace EFCoreExcercises.Services;

    public interface IProductService
    {
        Task<IEnumerable<Product>> GetAllAsync();
        Task<Product?> GetByIdAsync(int id);
        Task<Product> CreateAsync(Product product);
    }

STEP 5.2 - Implementation  (Services/ProductService.cs)

    using EFCoreExcercises.Data;
    using EFCoreExcercises.Models;
    using Microsoft.EntityFrameworkCore;

    namespace EFCoreExcercises.Services;

    public class ProductService : IProductService
    {
        private readonly AppDbContext _db;

        public ProductService(AppDbContext db) => _db = db;

        public async Task<IEnumerable<Product>> GetAllAsync()
            => await _db.Products.ToListAsync();

        public async Task<Product?> GetByIdAsync(int id)
            => await _db.Products.FindAsync(id);

        public async Task<Product> CreateAsync(Product product)
        {
            _db.Products.Add(product);
            await _db.SaveChangesAsync();
            return product;
        }
    }

STEP 5.3 - Register in Program.cs (before builder.Build())

    using EFCoreExcercises.Services;

    builder.Services.AddScoped<IProductService, ProductService>();

  DI LIFETIMES - pick the right one:
    AddScoped      one instance per HTTP request   (DEFAULT for most services
                   and anything that uses a DbContext)
    AddTransient   new instance every time it is requested (lightweight,
                   stateless helpers / validators)
    AddSingleton   one instance for the whole app  (caches, config holders;
                   NEVER inject a DbContext into a singleton)

 6. ADDING A CONTROLLER
------------------------------------------------------------------------------

OPTION A - Create manually (recommended, full control)
  Create Controllers/ProductsController.cs:

    using EFCoreExcercises.Models;
    using EFCoreExcercises.Services;
    using Microsoft.AspNetCore.Mvc;

    namespace EFCoreExcercises.Controllers;

    [ApiController]
    [Route("api/[controller]")]
    public class ProductsController : ControllerBase
    {
        private readonly IProductService _service;

        public ProductsController(IProductService service) => _service = service;

        [HttpGet]
        public async Task<IActionResult> GetAll()
            => Ok(await _service.GetAllAsync());

        [HttpGet("{id:int}")]
        public async Task<IActionResult> GetById(int id)
        {
            var product = await _service.GetByIdAsync(id);
            return product is null ? NotFound() : Ok(product);
        }

        [HttpPost]
        public async Task<IActionResult> Create(Product product)
        {
            var created = await _service.CreateAsync(product);
            return CreatedAtAction(nameof(GetById), new { id = created.Id }, created);
        }
    }

  The controller is picked up automatically by app.MapControllers()
  (already in Program.cs). No registration needed. Run the app and the
  endpoints appear in Swagger.

OPTION B - Scaffold with the CLI (generates CRUD against the DbContext)
  Requires the code generator tool + package:

    dotnet tool install --global dotnet-aspnet-codegenerator
    dotnet add package Microsoft.VisualStudio.Web.CodeGeneration.Design

  Then generate:

    dotnet aspnet-codegenerator controller `
        -name ProductsController `
        -api `
        -m Product `
        -dc AppDbContext `
        -outDir Controllers

  (In PowerShell the backtick ` is the line-continuation character. On one
   line, drop the backticks.)

 7. ADDING VALIDATION WITH FLUENTVALIDATION
------------------------------------------------------------------------------

STEP 7.1 - Create a validator  (Validators/ProductValidator.cs)

    using EFCoreExcercises.Models;
    using FluentValidation;

    namespace EFCoreExcercises.Validators;

    public class ProductValidator : AbstractValidator<Product>
    {
        public ProductValidator()
        {
            RuleFor(p => p.Name).NotEmpty().MaximumLength(100);
            RuleFor(p => p.Price).GreaterThan(0);
        }
    }

STEP 7.2 - Register validators in Program.cs (before builder.Build())

    using FluentValidation;
    using FluentValidation.AspNetCore;

    builder.Services.AddFluentValidationAutoValidation();
    builder.Services.AddValidatorsFromAssemblyContaining<Program>();

  AddValidatorsFromAssemblyContaining<Program> auto-registers EVERY validator
  in the project, so you do not list them one by one.

 8. CONFIGURING SERILOG (structured logging)
------------------------------------------------------------------------------

STEP 8.1 - In Program.cs, at the very TOP (after the using statements,
           before AddControllers):

    using Serilog;

    builder.Host.UseSerilog((context, config) =>
        config.ReadFrom.Configuration(context.Configuration));

STEP 8.2 - Enable request logging (after the app is built, early in the
           pipeline):

    app.UseSerilogRequestLogging();

STEP 8.3 - Configure sinks in appsettings.json (replace the "Logging" block
           or add alongside it):

    "Serilog": {
      "MinimumLevel": {
        "Default": "Information",
        "Override": { "Microsoft.AspNetCore": "Warning" }
      },
      "WriteTo": [
        { "Name": "Console" },
        {
          "Name": "File",
          "Args": {
            "path": "Logs/log-.txt",
            "rollingInterval": "Day"
          }
        }
      ]
    }

  Then inject ILogger<T> into controllers/services as usual, e.g.:
      private readonly ILogger<ProductsController> _logger;

 9. END-TO-END WORKFLOW FOR A NEW FEATURE (checklist)
------------------------------------------------------------------------------

To add a new feature (e.g. "Orders"):

    [ ] 1. Add entity        -> Models/Order.cs
    [ ] 2. Add DbSet         -> Data/AppDbContext.cs  (public DbSet<Order> ...)
    [ ] 3. Migration         -> dotnet ef migrations add AddOrders
    [ ] 4. Update DB         -> dotnet ef database update
    [ ] 5. (opt) DTOs        -> DTOs/OrderDto.cs
    [ ] 6. (opt) Validator   -> Validators/OrderValidator.cs
    [ ] 7. Service interface -> Services/IOrderService.cs
    [ ] 8. Service impl       -> Services/OrderService.cs
    [ ] 9. Register service  -> Program.cs  (builder.Services.AddScoped<...>)
    [ ] 10. Controller       -> Controllers/OrdersController.cs
    [ ] 11. Build & run      -> dotnet build  then  dotnet run
    [ ] 12. Test in Swagger  -> https://localhost:7133/swagger

 11. NOTES ABOUT RUNNING IN DOCKER (Linux container)
------------------------------------------------------------------------------

This project targets Linux containers (Dockerfile + DockerDefaultTargetOS).

  * Run "dotnet ef database update" from your HOST machine (not inside the
    debug container). The container is for running the app, not for tooling.

  * If your database also runs in Docker, the connection string host inside
    the app container is the DB service/container name or host.docker.internal,
    NOT "localhost". Example for SQL Server on the host:
        Server=host.docker.internal,1433;...

  * Secrets (connection strings with passwords) for local dev: prefer
    user-secrets over committing them to appsettings.json:
        dotnet user-secrets set "ConnectionStrings:DefaultConnection" "<value>"
    (UserSecretsId is already configured in the .csproj.)

 12. ADDING FILES / FOLDERS SO THEY APPEAR IN THE SOLUTION
------------------------------------------------------------------------------

This is an SDK-style project (<Project Sdk="Microsoft.NET.Sdk.Web">), which
means EVERYTHING physically inside the project folder is part of the project
automatically. There is no need to register files in the .csproj like the
old-style projects required.

  * .cs files       -> automatically compiled.
  * other files     -> automatically shown in Solution Explorer and can be
                       edited, but are not compiled.

So instructions.txt and .gitignore already belong to the project just by
existing in the folder. A few practical points:

--- 12.1 If a file does NOT show up in Solution Explorer ---------------------

  1. In Solution Explorer, click the "Show All Files" toolbar button
     (top of the Solution Explorer panel). Hidden/uncommitted files appear
     greyed out.
  2. Right-click the greyed-out file -> "Include In Project" (optional;
     for SDK-style projects this is usually unnecessary).
  3. Press the refresh button or reload the solution if it is stale.

--- 12.2 Creating files/folders FROM Visual Studio --------------------------

  * New folder    : right-click the project -> Add -> New Folder.
  * New file      : right-click a folder -> Add -> New Item...  (Ctrl+Shift+A)
  * Existing file : right-click -> Add -> Existing Item...  (copies it in).

--- 12.3 Creating files/folders FROM the terminal ---------------------------

  New-Item -ItemType File  instructions.txt          (a file)
  New-Item -ItemType Directory  Services             (a folder)

  They appear in Solution Explorer automatically (use "Show All Files" /
  refresh if needed).

  create using above command and include it inside the csproj file:
      <ItemGroup>
        <None Include="instructions.txt" />
      </ItemGroup>

example for folder:
      <ItemGroup>
        <Folder Include="Services\**\*" />
      </ItemGroup>

--- 12.4 Controlling what a non-code file does (optional) -------------------

  By default a text/doc file is "None" (just shown, not copied on build).
  To make a file copy to the output/publish folder, add this to the .csproj:

      <ItemGroup>
        <None Update="instructions.txt">
          <CopyToOutputDirectory>PreserveNewest</CopyToOutputDirectory>
        </None>
      </ItemGroup>

  CopyToOutputDirectory values:
      Never           (default) - do not copy
      PreserveNewest  - copy only if newer (most common)
      Always          - copy every build

  To EXCLUDE a file/folder from the project entirely:

      <ItemGroup>
        <Compile Remove="ScratchFolder/**" />
        <Content Remove="ScratchFolder/**" />
        <None    Remove="ScratchFolder/**" />
      </ItemGroup>

--- 12.5 "Solution Items" (files attached to the .sln, not the project) ------

  To attach a file at the SOLUTION level (e.g. a README shared by many
  projects) rather than to this project:
      Right-click the SOLUTION node -> Add -> New Solution Folder
      -> right-click that folder -> Add -> Existing Item...
  These live under a virtual "Solution Items" folder and are not built.

 13. .GITIGNORE
------------------------------------------------------------------------------

A .gitignore controls which files Git ignores (build output, IDE temp files,
secrets, etc.) so they are never committed.

--- 13.1 Generate the standard .NET .gitignore -----------------------------

  Run from the project folder:

      dotnet new gitignore

  This drops in Microsoft's official template, which already ignores:
      bin/  obj/          build output
      .vs/                Visual Studio working folder
      *.user *.suo        user-specific IDE files
      .env                environment/secret files
      and many more (test results, packages, publish output, etc.)

  (This project already has a .gitignore created this way.)

--- 13.2 If files were committed BEFORE being ignored -----------------------

  .gitignore only affects UNtracked files. If bin/ or obj/ were already
  committed, stop tracking them (this keeps the files on disk):

      git rm -r --cached bin obj
      git commit -m "Stop tracking build output"

--- 13.3 Add your own ignore rules ------------------------------------------

  Append lines to .gitignore, for example:

      # local logs produced by Serilog
      Logs/

      # local SQLite database
      *.db

  Check what Git currently sees:
      git status
      git status --ignored      (also lists ignored files)
